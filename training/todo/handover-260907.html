    The sequence

    The numbering is real. You cannot verify the live feed before you push, and you should not push before you have read the cards.

    02

    Read the 16 cards

    Local 20 min

    Read them, do not diff them. Nothing in this phase can be automated, because what you are judging is whether the wording is right in two languages. 

    • make dev

      Open http://localhost:4040/ and http://localhost:4040/de/. Use localhost, not 0.0.0.0: Firefox refuses the latter.

    • These are the new ones:

      • #msa-online-sep-2026, Wolfgang Reimesch
      • #msa-27-02-online, Wolfgang Reimesch
      • #improve-apr-2027, Wolfgang Reimesch. This one rendered as an HTML comment for weeks: it validated, it was in the feed, and it was invisible on both home pages.

      On each, check in order: no city line, the date ends in (online), the delivery-language note, the Berlin time-zone note, the trainer, the price, the terms link.

      Expect on the September MSA online date
      September 29 - October 1, 2026 (online) held in English Time zone: CET/CEST (Berlin) Trainer: Wolfgang Reimesch. €2,100

      29. September - 1. Oktober 2026 (online) Durchführung auf Englisch Zeitzone: MEZ/MESZ (Berlin) Trainer: Wolfgang Reimesch. 2.100 €

    • German is 2.100 €: thousands dot, symbol after. English is €2,100: comma, symbol before. This is built by hand in _includes/money.html because Liquid has no number formatter, so it is exactly the kind of thing that is either right or embarrassing.

      Same for credits: 20 methodische und 10 technische has to read as German, 20 methodology and 10 technical as English. A half-translated CPSA-Credits: label is the old bug returning.

    03

    Card price against booking panel

    Local 10 min

    The card and the panel render the same number by different routes. Agreement between two renderings of one number is precisely the thing that breaks quietly. 

    • http://localhost:4040/anmeldung/?kurs=msa-online-sep-2026
http://localhost:4040/registration/?kurs=msa-27-02-online

      The course must preselect from the query string. An unknown anchor must fall back to no selection, never to the first course in the list.

    • A mismatch here is what exposed the hardcoded price literals in the first place: the card showed a price the panel knew nothing about.

    • Inspect the DOM for _gotcha and company_website. Looking at the rendered page proves nothing, since a working honeypot is invisible by design.

    • Expect
      26-09 MSA-EN 27-02 MSA-EN

      The <option value> is the booking code your back office receives. Language hints belong in the label, never in the value.

    04

    Break the guardrails on purpose

    Local 15 min
    The rule that caused last week's confusion

    A guardrail proof and a real failure print identical text. An error only counts on a tree you have not touched. End every proof by restoring the file and running the validator until it says OK again. 

    • git mv _includes/timeline_msa_online.html /tmp/
ruby scripts/validate_trainings.rb ; echo "exit=$?"
      Expect

      Exit 1, with one error for each of the two online MSA dates, naming the missing file and the when "msa_online" case to add.

      git mv /tmp/timeline_msa_online.html _includes/
ruby scripts/validate_trainings.rb   # OK: 4 courses, 16 dates

    • Rename a course id in _data/trainings.yml to something no template matches, for example adocx. Every date under it must error. Then:

      git checkout _data/trainings.yml
ruby scripts/validate_trainings.rb   # OK again

      This is the failure mode that shipped improve-apr-2027 as an invisible date. Seeing it fire once is worth more than trusting that it would.

    05

    Prove the early bird expires

    Local 15 min

    This is the behaviour the whole restructuring exists for: an offer that lapses without anyone editing anything. Half of it can be observed on real data right now.

    • msa-dez-2026's early bird ran out on 8 August 2026, which is in the past. It should already be gone from the build, with no clock trickery at all. Check _site/api/trainings.json:

      msa-dez-2026  pricing: "2.890 €"
              price:   {"amount":2890,"currency":"EUR"}   <- no early_bird key

msa-mar-2027  pricing: "Frühbucherpreis bei Anmeldung bis
                        2. November 2026: 2.690 €, Normalpreis: 2.890 €"
              price:   {... "early_bird":{"amount":2690,"until":"2026-11-02"}}

      An expired offer is omitted from the feed entirely. Consumers must never have to check a date themselves.

    • Set msa-mar-2027's early_bird.until to "2026-01-01", then make site. The offer must vanish from all four places:

      • the card in _site/index.html and _site/de/index.html
      • the data-price attribute in both built registration pages
      • pricing in _site/api/trainings.json
      • price.early_bird, which must be absent, not merely ignored
    • ruby scripts/validate_trainings.rb   # still OK
git checkout _data/trainings.yml

      That is deliberate. An expired offer is inert, and deleting it by hand would lose the record of what was once offered.

    06

    Admin app warnings

    Local 15 min 
    • make app-demo       # http://localhost:8080
                    # reads _data/trainings.yml, never writes it
                    # publishing writes to demo-out/ and opens nothing

      Stop it afterwards with make app-stop. Note that make stop does not stop the demo.

    • Add a course with an id no template matches, for example flow. Read the warning bar and cancel. It should name _includes/timeline_flow.html, timeline_flow_online.html and their cases in timeline_course.html.

    • This is the case that matters most to you. Most of Wolfgang's runs are online, and a false alarm here would train you to ignore the warning bar. Do the same for an online REQ4ARC date: that template was added ahead of the first such course, so it should be silent too.

    • Set the early-bird amount at or above the regular price. This must be rejected, not warned about.

      Where these warnings come from

      The lists live in admin-app/internal/model/model.go and mirror the real _includes/ directory. That mirror can drift. When it does, the cost is a wrong advisory, never a wrong file, because scripts/validate_trainings.rb checks the actual directory in CI and is the authority.

    07

    Merge, push, watch it deploy

    Ship 15 min plus wait
    The one-way door

    Everything before this is private to your machine. Everything after it is visible to customers and to four other repositories. Do not start phase 7 with phases 2 to 5 unfinished.

    • git checkout main
git merge prices-as-data
git push origin main

      Local main also carries one unpushed commit, ae0612c. The push sends both, which is what you want.

      • validate-trainings.yml runs, because _data/trainings.yml, scripts/** and the schema all changed.
      • GitHub Pages rebuilds the site and the feed.
      • notify-consumers.yml fires, because _data/trainings.yml changed on main. It polls the published generated timestamp until Pages has caught up, up to ten minutes, then dispatches to all four consumer repositories.

      A missing CONSUMER_DISPATCH_TOKEN is a notice, not a failure. Consumers then pick the change up on their weekly schedule instead.

    • curl -s https://trainings.arc42.org/api/trainings.json | python3 -c '
import json,sys
d=json.load(sys.stdin); n=[x for c in d["courses"] for x in c["dates"]]
print(d["generated"])
print(len(n),"dates,",sum(1 for x in n if x.get("price")),"priced")
print("legacy pricing on all:", all("pricing" in x for x in n))
'
      Expect

      16 dates, 16 priced and legacy pricing on all: True. Today the same command prints 15 dates, 0 priced.

    08

    The four consumer sites

    Live 20 min

    Two things change for consumers, and neither is a schema break. The field names and types are untouched; the values are not.

      • The legacy pricing string moved from € 2690 to 2.690 €. Same field, same type, different text.
      • IMPROVE, REQ4ARC and ADOC had their prices hardcoded in this repository's own card templates, so they never reached the feed at all. Consumers showed nothing for them and will now show a price.
      • arc42.de and arc42.org: a bot commit to their _data/trainings.json, then prices rendering on their Termine pages. Read the German.
      • docs.arc42.org and faq.arc42.org: workflow green and pages unchanged. Neither renders a price, so a visible diff there means something consumes the feed more broadly than expected and is worth understanding.

      No consumer build should fail. One that does is parsing the string rather than printing it, which is worth knowing about regardless.

    • Known follow-up, not a blocker

      arc42.de still has its own hardcoded price literals in its own copy of the timeline templates. Until those go, it may show its literal rather than the feed's price. Find out which one wins. If they disagree, that is a new task, not a reason to roll back.

    After the rollout

    Deferred: 3 November 2026

    msa-mar-2027's early-bird deadline is 2 November 2026. Nobody will edit anything. The Monday rebuild (weekly-refresh.yml, 04:43 UTC) is what turns the passing of a date into a content change. There is already a Todoist task dated for it.

    If the offer is still being advertised on 3 November, the failure is in the rebuild cadence, not in the rendering: check that the weekly refresh ran and that the consumers' own refresh workflows are green. Remaining deadlines after that one: 8 Feb 2027, 14 May 2027, 30 Jul 2027.

    If it goes wrong

    Revert the merge commit on main. Consumers recover on their next refresh, weekly at worst, immediately via notify-consumers.yml. No consumer change is needed to roll back, which is the entire reason the legacy string fields were kept rather than cleaned up.
